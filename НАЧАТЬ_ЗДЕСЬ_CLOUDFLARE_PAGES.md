# 4-AI Hub — публикация без токенов Worker Builds

## Самое важное

Создавай **Cloudflare Pages**, а не Worker. Проект содержит Pages Function по пути `functions/api/provider/[[path]].js`. Именно поэтому публикация как статического Worker была неподходящей.

## Перед началом

- Не удаляй GitHub-репозиторий.
- Не удаляй старый Worker, пока новая Pages-версия не откроется и не будет проверена.
- В репозитории GitHub файлы должны находиться в корне: `index.html`, `functions/`, `assets/`, `css/`, `js/`, `tests/`.
- Ветка публикации: `main`.

## Создание нового проекта

1. Открой Cloudflare Dashboard.
2. Перейди в **Workers & Pages**.
3. Нажми **Create application**.
4. Выбери вкладку/вариант **Pages**.
5. Нажми **Connect to Git** и подключи GitHub, если Cloudflare попросит.
6. Выбери существующий репозиторий 4-AI Hub.
7. Укажи имя, например `4-ai-hub` (если оно свободно), и ветку `main`.
8. В настройках сборки выставь значения из таблицы.

| Поле | Значение |
|---|---|
| Framework preset | `None` |
| Build command | `exit 0` |
| Build output directory | `.` |
| Root directory | Оставить пустым |
| Preview command | Если поле вообще есть — оставить пустым |
| Deploy command | В настройках Pages такого поля быть не должно; не настраивай Workers Build |

Нажми **Save and Deploy**.

## Нужен ли API-токен?

Для обычной публикации Pages через GitHub отдельный `CLOUDFLARE_API_TOKEN` или `CLOUDFLARE_ACCOUNT_ID` не нужен. Не вставляй секрет Cloudflare в команду сборки и не добавляй его просто «на всякий случай». GitHub подключается через авторизацию Cloudflare Git integration.

API-ключи ChatGPT/OpenAI, Claude/Anthropic, Gemini или Grok/xAI — это отдельные ключи провайдеров. Пользователь вводит их в самом приложении. Не отправляй их в чат и не добавляй в GitHub.

## После публикации

1. Открой выданный адрес `*.pages.dev`.
2. Проверь, что интерфейс загружается.
3. Открой настройки ключей приложения и проверь диагностику соединения. Для реального ответа нейросети нужен действующий API-ключ соответствующего провайдера и доступ/квота у него.
4. Только после успешной проверки решай, удалять ли старый Worker. Он не является GitHub-репозиторием; удаление Worker не должно удалять файлы из GitHub, но лучше оставить старый вариант, пока новая страница не заработала.

## Если новая Pages-сборка не прошла

Открой **Pages project → Deployments → View build log** и пришли только текст ошибки. Не присылай API-ключи, токены, пароли или значения Secret.
