# 4-AI Hub

Лёгкий веб-интерфейс для совместной работы Grok, ChatGPT (OpenAI API), Claude и Gemini. Проект не требует npm-сборки: используется обычный HTML, CSS и JavaScript.

## Что обновлено

- Восстановлена проверка каждого ключа отдельно; результат показывает провайдера, код/причину ошибки и доступные модели.
- Модель выбирается из списка, который действительно возвращает API-ключ, вместо одного жёстко заданного имени.
- Временная ошибка сети, тайм-аут, лимит или ошибка сервера пропускают узел только на время текущего задания. При следующем задании временно отказавший узел пробуется снова. Однозначно отклонённый API-ключ отмечается отдельно.
- Добавлены тайм-аут запросов, подробные сообщения об ошибках, переключение на следующий доступный узел и остановка текущего задания.
- Добавлена необязательная «Тестовая генерация». Она отправляет короткий запрос к каждой модели и может расходовать небольшую часть API-квоты. Без этого флажка проверяется авторизация и список моделей без тестовой генерации.
- На карте можно выбрать модель и открыть справа панель её состояния, этапа, текущей задачи и последнего ответа. Кнопка «Далее» переключает панель между подключёнными моделями.
- Логотип из предоставленного изображения появляется на заставке и плавно перемещается в левый верхний угол. Для Grok, ChatGPT, Claude и Gemini используются отдельные изображения логотипов, взятые из предоставленного изображения.
- При чтении текстовых вложений учитываются лимиты контекста; большие файлы не загружаются целиком в память браузера. Эта статическая версия передаёт в запрос текстовые фрагменты; содержимое бинарных файлов (например, архивов, PSD или EXE) не загружается в модели.

## Публикация на Cloudflare Pages

Прокси для API расположен в `functions/api/provider/[[path]].js`. На Cloudflare Pages он позволяет отправлять запросы к провайдерам через тот же сайт и обходить типичные ограничения CORS, которые мешают прямым запросам браузера.

1. Загрузите в репозиторий **содержимое этой папки** так, чтобы `index.html`, `functions/`, `assets/`, `css/`, `js/` и `_headers` были в корне сайта.
2. В Cloudflare Pages подключите репозиторий. Команда сборки не нужна; папкой публикации выберите корень проекта, в котором лежит `index.html`.
3. Убедитесь, что `functions/api/provider/[[path]].js` попал в корень проекта. Cloudflare Pages Functions разворачиваются вместе с сайтом автоматически.
4. После публикации откройте сайт и проверьте ключи. Если запустить проект на локальном статическом сервере без Pages Functions, он попробует прямые запросы; они могут блокироваться CORS у некоторых провайдеров.

## Ключи и безопасность

- API-ключи вводит пользователь и хранит браузер в `localStorage`. Не добавляйте настоящие ключи в GitHub, README, скриншоты или файлы проекта.
- Pages Function не сохраняет ключи и не выводит их в журналы; она принимает только ограниченный набор маршрутов четырёх указанных провайдеров и отклоняет запросы с другого origin.
- Ключ всё равно доступен JavaScript в вашем браузере. Не запускайте неизвестные скрипты на странице с сохранёнными ключами и не размещайте сайт с этим способом хранения в недоверенной среде.
- Если проверка завершилась сетевой ошибкой, ключ не объявляется автоматически неверным: в карточке указывается, что подтвердить его не удалось. Успешный ответ `/models` подтверждает доступ к списку моделей, но не гарантирует успешную генерацию; для этого можно поставить флажок тестового запроса.

## Структура

- `index.html` — интерфейс, карта узлов и панель просмотра модели.
- `js/providers.js` — модели, проверка ключей, вызовы API и выбор резервной модели.
- `js/app.js` — онбординг, состояние узлов, очередь этапов, чат и вложения.
- `functions/api/provider/[[path]].js` — защищённый allowlist-прокси для Cloudflare Pages.
- `assets/brand-logo.png` — основной логотип-заставка; `assets/providers/` — отдельные логотипы провайдеров.
- `css/style.css` — минималистичный адаптивный интерфейс и анимации.

## Проверки кода

Синтаксис JavaScript можно проверить локально командой:

```sh
node --check js/providers.js
node --check js/app.js
node --test tests/*.test.cjs
```

Для реальной проверки соединения понадобятся собственные ключи API; здесь ключи не были предоставлены, поэтому успешные запросы к платным/авторизованным API не заявляются.
